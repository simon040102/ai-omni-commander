# Brainstorm Methodology

When starting a new feature or complex task, follow this structured approach:

## Phase 1: Discovery
1. **Clarify requirements** - Ask clarifying questions before writing any code
2. **Understand the "why"** - What problem are we solving? What's the desired outcome?
3. **Identify constraints** - Performance, compatibility, existing patterns to follow

## Phase 2: Design
1. **Explore alternatives** - Consider at least 2-3 different approaches
2. **Evaluate trade-offs** - Compare complexity, maintainability, performance
3. **Document the chosen approach** - Write a brief design summary

## Phase 3: Validation
1. **Present the plan** - Show the design in digestible chunks
2. **Get sign-off** - Wait for user confirmation before proceeding
3. **Break into tasks** - Split into small, testable pieces (2-5 minute chunks)

## Rules
- Never jump straight to coding for non-trivial features
- Design documents should be short and focused
- Each task should have clear success criteria
- Complexity reduction is a primary goal
