# AI-OmniCommander

## AI 協作開發指揮中心 — 功能說明

---

## 這是什麼？

一個 MCP Server + 可選 Web UI，讓 Claude Code 能：

- 管理多個軟體開發專案
- 自動從 Asana 同步任務、從 SVN + 本地資料夾抓規格文件
- 用規格檢查表 + AI 回對閘門確保「做的跟規格一樣」才算完成
- 派 AI subagent 平行開發前後端
- 即時監控進度、追蹤待補規格與專案經驗

**一次註冊、到處可用**：user-scope 註冊後，在任何專案資料夾開 Claude Code 都能使用；工具與使用規則由 MCP 協定自動注入，不用改任何 CLAUDE.md。

---

## 現行工作流

```
列專案 → 同步 Asana → 選任務 → 自動判軌（bug 無規格→light / 規格驅動→full）
→ 抓規格（SVN + 本地規格資料夾雙來源）→ 抽規格檢查表（checklist）
→ [full 軌] Flow-Gated 開工閘（規格理解確認，原閘門 A）/ 完工閘（實作邏輯對齊，原閘門 B）→ 開發（先列測試案例清單 → 寫測試 → 全綠）
→ 程式預檢（run_spec_compliance）→ AI 回對（獨立 agent 逐項驗證，missing=0）
→ 驗收（get_verification_plan + 單元測試通過回報 + 證據上傳）→ completed（閘門放行）
```

**自動判軌**：小型 bug（無 SA/SD 規格）自動走 light 軌 — 跳過流程圖閘門、檢查表改抽 BUG 原文；規格驅動的任務走 full 軌。輕的是工序不是標準：兩軌都要 AI 回對 missing=0 才能標 completed。

**配套機制**：

- **規格缺口**（`report_spec_gap`）— 規格沒定義的東西記錄下來，不自行編造；Web UI 有待補規格面板
- **專案經驗筆記**（`save_project_note`）— 專案特有的坑記一次，之後每個執行計畫自動注入
- **規格異動偵測**（`check_spec_changes`）— Asana 同步後自動跑，規格被改會自動開缺口提醒
- **SA/SD 一致性檢查**（`check_spec_consistency`）— 開工前先抓規格自相矛盾
- **接手舊任務**（`resume_task`）— 一次恢復摘要、閘門進度、歷史回報、未解缺口、最近派工快照
- **任務推薦**（`next_task`）— 依賴未阻塞 + bug 優先，並主動列出疑似停滯任務
- **卡死偵測** — in_progress 任務帶停滯時數（預設 24h 門檻），殭屍任務不再沉默腐爛
- **派工快照**（`save_task_dispatch`）— session 被中斷後，任何新 session 都能取回原始派工 prompt 續派

## 完成閘門與防護

「不測不能結、不回對不能結、不准編造、不准自評」——這些不靠 AI 自律，是程式強制。

### 完成閘門（`update_task_status(completed)` 六道，全數通過才放行）

1. **完工閘（實作邏輯對齊）** — 流程圖閘門（依軌道）
2. **檢查表存在** — 有軌道就必須有規格檢查表，防「空跑結案」
3. **AI 回對 missing=0** — 最新一次獨立 reviewer 的逐項判定，含 staleness 防護（回對後新增的檢查項也必須被涵蓋）
4. **單元測試閘門** — 專案有設 `frontendTestCommand`/`backendTestCommand` 時，「單元測試全數通過」驗收必須 passed=true
5. **執行計畫/派工記錄閘門** — 開發任務（frontend/backend/fullstack）必須有 `get_execution_plan` 寫入的 track、`[TRACK]` 稽核行或 `save_task_dispatch` 的 `[DISPATCH]` 派工快照其一，防繞過執行計畫直接開工結案
6. **驗收 FAIL 擋結案** — 任何驗收項最新一筆 `report_verification_result` 為 FAIL 即拒絕（修復後重跑並回報 passed 再結案；從未回報的項目不擋）

逃生口：`skipFlowGate` + 理由，**限使用者明確同意**，記 `[SKIP]` 稽核軌跡。

### AI 回對嚴謹度（四層）

1. **AI 逐項判定** — matched 必附 file+line 證據
2. **證據程式驗證** — 開檔驗證行號 ±10 行內確實含該文字/路徑/識別字，引用不實**整批退回**
3. **引擎×AI 分歧偵測** — 與程式預檢判定相反的項目標 ⚡，作為人工抽查靶點
4. **反向完整性掃描** — reviewer 重掃規格原文，找出檢查表漏抽的項目補上

配套鐵律：implementer 不可自評（reviewer 必須是全新 context 的獨立 agent）；結果必須涵蓋所有未豁免項目。

### 行為防護

- **spawn 硬閘** — `ALLOW_LEGACY_SPAWN` 未設時，本機 spawn 派工一律拒絕（執行只走外部 session + MCP）
- **禁裝擋板** — 測試指令因缺框架失敗 → 嚴禁自行安裝套件/修改建置檔，標 failed 交回使用者
- **無關失敗護欄** — 只准動與本任務相關的測試；撞到既有無關失敗 → 誠實揭露於 note，不卡結案也不准順手修
- **稽核軌跡** — `[SKIP]`（跳閘）/`[CHECKLIST_REPLACE]`（回對後整份取代檢查表）/`[TRACK]`（軌道判定）/`[DISPATCH]`（派工快照），Web UI 直接標 completed 也記 `[SKIP]`

### 安全面

- 憑證保護：SVN 密碼走 stdin 不上命令列、API 回應與 log 全遮罩、DB Explorer 憑證欄位遮罩、mcp-notify 共享 token（timing-safe 比對）
- 注入防護：SQL 全參數綁定、git 指令白名單（只允許 status/rev-parse/log/pull --ff-only）、上傳與證據路徑 containment
- `query_external_db` 只允許單一 SELECT（建議搭配唯讀 DB 帳號）
- 非 loopback 綁定（`HOST=0.0.0.0`）啟動時大字警告

### 資料韌性

- `omni.db` 啟動時 + 每 24 小時自動備份（保留最近 10 份，`data/backups/`）
- Migration 表重建包交易，程序中途崩潰或雙 process 同時啟動不會留下半成品

## Prompt 自動注入（工具回傳的派工計畫做了什麼）

**Server instructions（MCP 連線自動注入）**：每個連上的 session 自動被要求——開工先 `get_execution_plan`、規格一律從工具取得、規格沒定義就 `report_spec_gap` 不可編造、結束必回報狀態。

**`get_execution_plan`（開發 agent 的派工 prompt）**：

- 自動判軌（full/light），light 軌檢查表改抽 BUG 原文
- 注入六大規範全文：規格文件閱讀、規格遵循最高原則、**單元測試強制流程**（先列案例清單留稽核 → 失敗案例預期值必須有規格出處 → 寫到綠 → 完成前全套再跑）、後端效能分析（禁撈全表）、後端安全檢查、狀態回報
- 自動附上：專案 extraPrompt（技術棧慣例）、專案經驗筆記、規格文件完整路徑（**不摘要**——讓 agent 讀原文，防轉述錯誤）

**`get_compliance_review_plan`（AI 回對 reviewer 的派工 prompt）**：

- 兩軌模板 + 檢查表分頁指示（大檢查表自動縮頁、hasMore 可信）
- **元件知識庫注入**（`category="component"` 專案筆記）— 已確認的元件級事實直接給 reviewer，降重複追查的 token 成本；附「不是免驗證通行證」框架
- **引擎證據種子** — 程式預檢已 matched 的項目附 file:line，reviewer 開檔確認即沿用，時間集中在 missing/manual/logic 項
- 回寫閉環 — reviewer 把新確認的元件事實存回筆記，知識庫自動滾大

**`get_test_baseline_plan`（基線修復 fixer 的派工 prompt）**：每條失敗強制三分類（測試化石=依規格修斷言／真 bug=不改、另開任務／環境問題=只回報），**嚴禁把程式現狀當正確答案改寫斷言**。

**`start_task` MCP Prompt**：一鍵展開標準工作流（定位任務 → 計畫 → 執行 → 驗收 → 結案）。

## MCP 工具一覽（54 個）

Claude Code 啟動時自動載入，不需要開 Web Server。

### 任務 / 執行計畫

- `get_execution_plan` — 取得任務完整執行計畫（自動判 full/light 軌 + 注入品質規範）— 開工第一步
- `list_pending_tasks` — 待辦任務清單（taskType/label/keyword/section/tag/statuses 過濾）
- `get_task` — 任務詳情（`includeDocuments=true` 才含文件）
- `update_task_status` — 更新狀態（completed 受完成閘門管制）
- `update_task` — 更新任務欄位（title/label/taskType/tags/section）
- `next_task` — 推薦下一個可做任務
- `resume_task` — 接手舊任務的一站式脈絡恢復
- `get_task_outputs` — 取回任務歷史回報
- `save_task_dispatch` — 存派工快照（中斷復原用；resume_task 會帶回最近一次派工 prompt）
- `create_task` — 建立任務
- `add_task_dependency` / `remove_task_dependency` — 任務依賴（含循環偵測）

### 文件 / 規格

- `fetch_svn_specs` — 從 SVN + 本地規格資料夾雙來源抓 SA/SD（docx 自動轉 md，含快取）
- `get_documents` / `read_document` — 列出 / 讀取文件
- `search_documents` — 規格全文搜尋（行號 + 前後文，查欄位名/API 路徑省 context）
- `find_axure_snapshot` — 依功能代碼找 Axure 原型 HTML
- `fetch_task_attachments` — 下載 Asana 附件（BUG 截圖等）

### 規格缺口

- `report_spec_gap` — 記錄規格未定義的欄位/API/邏輯
- `list_spec_gaps` / `resolve_spec_gap` — 待補規格清單 / 標記已解決
- `check_spec_changes` — 偵測規格開工後被改（自動開 spec_changed 缺口）
- `check_spec_consistency` — SA/SD 互相矛盾檢查

### 規格回對（checklist / compliance）

- `save_spec_checklist` / `get_spec_checklist` — 抽取 / 取回規格檢查表
- `waive_checklist_item` — 豁免檢查項（必附理由）
- `run_spec_compliance` — 程式預檢（抓文字/路徑錯字；advisory，不解鎖閘門）
- `get_compliance_review_plan` — AI 回對派工計畫（派獨立 reviewer，implementer 不可自評）
- `save_compliance_review` — 寫回 AI 回對結果（missing=0 才解鎖 completed）

### 驗收

- `get_verification_plan` — 依任務 label 取驗收清單
- `get_test_baseline_plan` — 既有單元測試不是全綠時，取得基線修復計畫（先修基線再開發）
- `report_verification_result` — 回報逐項驗收結果
- `report_verification_evidence` — 上傳驗收證據（Playwright 截圖等）

### 專案筆記

- `save_project_note` — 記專案坑/慣例（自動注入後續執行計畫）
- `list_project_notes` / `archive_project_note` — 查看 / 封存

### Flow-Gated 流程圖

- `save_task_flow` — 儲存流程圖（spec/plan/code/mindmap）
- `report_flow_check` — 回報開工閘/完工閘（gate="A"/"B"）比對結果
- `get_task_flows` — 列出任務流程圖
- `save_sa_flow` — 儲存 SA Mermaid 流程圖快取

### Asana

- `sync_asana_tasks` — 同步任務（直打 REST API；5 分鐘去重；同步後自動偵測規格異動；**subtask 遞迴抓取**：專案清單抓不到未掛專案的 subtask，會對未完成任務遞迴抓到深度 3、只抓未完成、gid 去重、每次上限 300 支 API 超過截斷+警告，`includeSubtasks=false` 退回舊行為；**截止日繼承**：subtask 沒填 due date 時繼承最近有日期的祖先任務）
- `list_asana_projects` — 列 Asana 專案（找 GID 綁定用）
- `get_asana_task_comments` — 讀任務留言（支援 omni UUID 或 Asana GID）

### 進度回報

- `report_output` / `report_milestone` — 回報輸出 / 里程碑到 Web UI

### 專案 / 設定 / 診斷

- `list_projects` / `get_project` — 列出 / 取得專案
- `create_project` / `update_project` — 建立 / 更新專案（含規格資料夾設定）
- `set_extra_prompt` — 設定專案前端/後端 Extra Prompt
- `set_global_config` — 設定 SVN 帳密、Asana PAT（不用手動改 DB）
- `get_skill_gen_plan` — 產生 workspace CLAUDE.md/skills 的完整計畫
- `query_external_db` — 唯讀查詢專案綁定的外部 DB（列表、表結構、SELECT）
- `health_check` — 診斷 DB / Web Server / Asana PAT / SVN（畫面沒更新、撈不到規格先跑這個）

另有 MCP Prompt：`start_task` — 展開標準任務工作流（taskId 可省略，自動定位）。

## 規格文件雙來源

**SVN 自動抓取**：

```
任務名稱：WA04_已轉派工作清單
  → 提取功能代碼：WA04 → 根代碼：WA
  → SVN 搜尋：WA流程作業區/
  → 下載 SPEC_WA04_已轉派工作清單_v0.2.docx → 自動轉 Markdown
```

三層快取避免重複下載：SVN 日期沒變 → 不下載；SHA-256 沒變 → 不重轉換；DB 已有 → 直接用。

**本地規格資料夾（specFolders）**：規格放在本地磁碟、NAS 或 git repo 也能抓，與 SVN 結果合併。git 資料夾抓取前先安全 `git pull --ff-only`（working tree dirty 就跳過並警告，絕不寫入、絕不 stash/reset）。設定時強制絕對路徑，且禁止與程式碼 workspace 相同或互為父子。

## Web UI 功能（可選）

Web Server (:3457) 有跑才即時更新；沒跑時所有 MCP 工具照常可用。兩邊共用同一個 SQLite，可混用。

### 專案管理

- 建立專案（前端 / 後端路徑）
- 綁定 Asana 專案（自動同步任務）
- 設定 SVN 規格路徑、**規格資料夾（specFolders，含 git pull 開關）**
- 設定 Extra Prompt（附加給每個 subagent 的開發指示）
- 外部資料庫連線（查 schema 用）
- Gen Skills（自動分析專案產生 CLAUDE.md + skills）

### Dashboard

- 任務執行狀態、進度輸出、里程碑追蹤
- **規格治理收合區**（三面板）：
  - **待補規格** — report_spec_gap 記錄的缺口，補完可標已解決
  - **規格回對** — 檢查表項目與比對結果（matched / missing / waived）
  - **專案筆記** — 累積的專案經驗

### 全域設定

- SVN 帳密、Asana Personal Access Token（也可用 `set_global_config` 工具設）
- **桌面通知開關**（瀏覽器通知，見下方「通知」）

### 通知

任務事件有兩種通知管道，各自獨立開關：

- **伺服器端 Windows toast**（最可靠——瀏覽器不用開）：Web Server（:3457）在 Windows 上偵測到「任務 completed / failed」「agent 輸出含 `[NEEDS_HUMAN]`」「新規格缺口（report_spec_gap）」時，直接跳出系統 toast 通知。事件來源同時涵蓋 MCP 的 `/api/mcp-notify` 與 Web UI 直接改狀態（task.update）。
  - 開關：global_config key **`notify.windowsToast`**，值 `'0'` 或 `'false'` 停用，預設啟用（可用 `set_global_config` 工具設定）
  - 節流：同一則（標題+內容）30 秒內只發一次；全域每 10 秒最多 3 則，超過丟棄
  - 非 Windows 平台自動 no-op；通知失敗絕不影響主流程
- **瀏覽器桌面通知**（Web UI）：全域設定頁開啟「桌面通知」後（會請求瀏覽器通知權限），任務 completed / failed 時發 `Notification`。**只在分頁不在前景時發送**（前景看 UI 即可），點通知會切回分頁。開關狀態存於該瀏覽器的 localStorage（key `omni.desktopNotify`）。

> 註：「Claude Code 等待確認」的提醒不屬於 omni——由使用者自己的 Claude Code Notification hook 處理（orchestrator 另行設定）。

## 產生 Workspace Skills

`get_skill_gen_plan(projectId, workspaceType)` 產生完整計畫，派 Opus 級 subagent 深讀 codebase，為 workspace 產生或增強 `CLAUDE.md` 與 `.claude/skills/`：

- **官方 SKILL.md 資料夾格式**（`<skill-name>/SKILL.md`）
- 注入專案經驗筆記（歷來踩過的坑）
- 含「開發前必讀」章節

之後派去該 workspace 的 subagent 會自動讀取並遵循。
