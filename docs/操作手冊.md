## 1. 系統需求與安裝

### 前置需求

| 項目 | 版本需求 | 說明 |
|------|---------|------|
| Node.js | >= 20.0.0 | 執行環境 |
| pnpm | 最新版 | 套件管理工具 |
| Claude Code CLI | 最新版 | AI Agent 核心，需已登入 |
| SVN CLI | 1.14+ | 規格文件抓取（建議 SlikSVN 或 PATH 上的 svn） |
| Git | 最新版 | 版本控制 |

> V5 不再需要 C++ Build Tools（已移除 node-pty 依賴）。

### 安裝

```bash
git clone https://github.com/simon040102/ai-omni-commander.git
cd ai-omni-commander
git checkout OmniCommander_MCP

pnpm install
pnpm build
```

### SVN CLI 安裝

**Windows：**
- **推薦**：SlikSVN（[下載](https://sliksvn.com/download/)）— 純 CLI，自動加入 PATH
- **備選**：TortoiseSVN（需勾選 command line tools）

> 注意：TortoiseSVN 的 svn.exe 在 pipe 模式下會把中文字元變成 `?`。OmniCommander 已用 `--xml` 模式處理，但建議優先使用 PATH 上的 svn。

**macOS：**
```bash
brew install svn
```

### Claude Code CLI 安裝

```bash
npm install -g @anthropic-ai/claude-code
claude  # 首次執行會開瀏覽器 OAuth 登入
```

## 2. 啟動方式

### 方式 1：純 MCP 模式（推薦）

直接在專案目錄開 Claude Code，MCP Server 自動啟動：
```bash
cd ai-omni-commander
claude
```

Claude Code 讀 `.mcp.json` 後自動 spawn `server/dist/mcp-entry.js`。所有 MCP 工具（sync_asana_tasks、fetch_svn_specs 等）直接可用，**不需要額外啟動服務**。

### 方式 2：MCP + Web UI

```bash
# 終端 1：啟動 Web Server + Web UI
pnpm dev
# Server: localhost:3457
# Web UI: localhost:5174

# 終端 2：開 Claude Code
claude
```

Web UI 提供即時監控：agent 輸出、任務狀態、里程碑、SA 流程圖。

### 方式 3：VS Code 擴充

在 VS Code 裝 Claude Code 擴充，開啟 ai-omni-commander 資料夾，MCP Server 自動啟動。

## 3. 首次設定

### 3.1 設定 Asana PAT（可選）

```bash
cd server && node -e "
const Database = require('better-sqlite3');
const db = new Database('../data/omni.db');
db.prepare(\"INSERT OR REPLACE INTO global_config (key, value) VALUES ('asana.pat', '你的_PAT_TOKEN')\").run();
console.log('done');
"
```

或在 Web UI 的 Global Settings 頁面設定。

### 3.2 設定 SVN 帳密（可選）

```bash
cd server && node -e "
const Database = require('better-sqlite3');
const db = new Database('../data/omni.db');
db.prepare(\"INSERT OR REPLACE INTO global_config (key, value) VALUES ('svn.username', '你的帳號')\").run();
db.prepare(\"INSERT OR REPLACE INTO global_config (key, value) VALUES ('svn.password', '你的密碼')\").run();
console.log('done');
"
```

### 3.3 建立專案

在 Claude Code 裡對話：
```
使用者：幫我建一個專案叫「我的專案」，前端在 D:\fork\my-ui，後端在 D:\fork\my-api
```

### 3.4 綁定 Asana 專案（可選）

```
使用者：幫我綁定 Asana，project GID 是 1234567890
```

### 3.5 設定 SVN 規格路徑（可選）

透過 Web UI 的 Project Settings，或更新 `config_json`：
```json
{
  "svnConfig": {
    "frontendSpecPath": "https://svn.example.com/.../SA/",
    "backendSpecPath": "https://svn.example.com/.../SD/"
  }
}
```

### 確認安裝成功

在 Claude Code 裡：
```
使用者：有哪些專案
```
能列出專案就代表 MCP Server 正常。

## 4. 給 AI Agent 的操作指南

> 以下內容是給 Claude Code Agent 讀的。當你是 orchestrator 時，遵循此指南操作。

### 你的角色

你是 orchestrator。你**不直接修改任何專案的程式碼**。所有開發工作（bug、feature、refactor）都派 subagent 執行。

唯一例外：OmniCommander 自己的程式碼（server/、web/、CLAUDE.md）可以直接改。

### 架構

```
你（Orchestrator）
 ├─ OmniCommander MCP Server（stdio，自動 spawn）
 │   ├─ SQLite DB（data/omni.db）
 │   ├─ Asana REST API（PAT token）
 │   └─ SVN（帳密）
 │
 ├─ Agent tool → 派 subagent
 │   ├─ 前端 subagent（cwd = frontendPath）
 │   ├─ 後端 subagent（cwd = backendPath）
 │   └─ subagent 讀 workspace 的 CLAUDE.md + .claude/skills/
 │
 └─ Web UI（可選）— 即時監控
```

## 6. 完整操作流程

### Step 1：列出專案
```
使用者：「有哪些專案」
→ list_projects()
→ 整理成清單回覆
```

### Step 2：同步任務
```
使用者選了專案後：
→ sync_asana_tasks(projectId)  // 5 分鐘內同步過會跳過
→ list_pending_tasks(projectId)
→ 按功能代碼分組顯示（DF、WA、PM、SM...）
```

### Step 3：使用者選任務
```
使用者：「WA04」
→ 問「要做前端、後端、還是都做？」
```

### Step 4：自動抓取規格
```
→ fetch_svn_specs(projectId, taskId)     // SA/SD
→ ls axure-snapshots 找 Axure 原型
→ fetch_task_attachments(projectId, taskId)  // Asana 附件
→ 檢查規格齊全（前端需 SA+SD，後端需 SD）
→ 缺的話告知使用者
```

### Step 5：確認
```
→ 列出規格文件
→ 問「有額外文件嗎？沒有說執行」
→ 使用者說「執行」才派 subagent
```

### Step 6：讀專案 Extra Prompt
```
→ get_project(projectId)
→ 取 config_json.frontendExtraPrompt / backendExtraPrompt
→ {AXURE_SNAPSHOT_PATH} 替換成實際路徑
→ 原封不動加入 subagent prompt
```

### Step 7：派 subagent

見第 7 章。

### Step 8：驗證

見第 8 章。

## 7. Subagent 派遣規範

### 決定派幾個 agent

- 簡單功能（查詢+CRUD）→ 前端+串接**合併一個** agent
- 複雜功能（大量 UI + 複雜 API）→ 可分前端、串接兩個
- 後端 → 獨立一個 agent

### Subagent prompt 必須包含（按順序）

#### 1. Workspace 規範
```
1. 讀 {workspacePath}/CLAUDE.md
2. ls {workspacePath}/.claude/skills/
3. 讀相關 skill
4. 嚴格遵循
```

#### 2. Superpowers 方法論
- bug → /systematic-debugging
- feature → /brainstorming + /test-driven-development
- refactor → /brainstorming

#### 3. 規格文件路徑（只放路徑，嚴禁摘要）
```
讀 SA 文件：{path}
讀 SD 文件：{path}
讀 Axure：{path}
```

#### 4. 規格遵循規則
```
所有實作必須有規格依據。規格沒寫的不做，規格寫的照做。
- 欄位名、按鈕文字、訊息文字 → 從規格逐字抄
- API 路徑、參數名 → 從 SD 抄
- UI 元件選擇 → 從 SA/Axure 確認
- 不清楚 → 標 [NEEDS_CLARIFICATION]
```

#### 5. 後端專用：效能分析
```
寫 code 前先列：
1. 資料表 + 資料量估算
2. 每個查詢的 WHERE 條件 + 預期筆數
3. 迴圈內 DB 查詢檢查（N+1）
4. 端到端資料流回顧
禁止 findAll() + 記憶體過濾
```

#### 6. 後端專用：安全檢查
```
- SQL 參數用 @Param 綁定
- API 驗證當前使用者權限
- Controller 參數有長度/格式驗證
- response 不回傳敏感資料
- 批次操作有上限
- log 不印個資
```

#### 7. 專案 Extra Prompt（原封不動貼上）

#### 8. 狀態回報（prompt 開頭和結尾都要）
```
report_output(taskId, content)         — 每步回報
report_milestone(taskId, milestone)    — 重要節點
update_task_status(taskId, "completed", summary)  — 完成
update_task_status(taskId, "failed", summary)     — 失敗
```

## 8. 驗證流程

### Subagent 完成後，orchestrator 必須自己驗證

#### 後端任務
1. **靜態檢查**：`grep -rn "findAll()" ServiceImpl.java` — 不應該有
2. **DDL 比對**：CREATE TABLE 欄位名 vs Entity @Column name（特別是 MetaData 的 CREATE_DATE / MODIFY_DATE / DATA_REMARK）
3. **API 煙霧測試**：curl 每個新 API，確認回 200 不是 500
4. **seed SQL 檢查**：INSERT 欄位數 = VALUES 參數數

#### 前端任務
1. **tsc --noEmit**：TypeScript 零錯誤
2. **瀏覽器測試**：用 Playwright 開頁面操作（如果服務有跑）

**單元測試只驗邏輯，不驗 SQL 和欄位名。API 煙霧測試才是真正的驗收。**

## 10. SVN 規格文件整合

### 自動匹配規則

`fetch_svn_specs(projectId, taskId)` 執行時：

1. 從任務 `parent_name` 提取功能代碼（如 `WA04_已轉派工作清單` → `WA04` → root code `WA`）
2. 用 `svn list --xml` 搜尋 SVN 目錄（XML 輸出確保 UTF-8）
3. 找到匹配的資料夾（如 `WA流程作業區/`）
4. 遞迴搜尋 `.docx` / `.pdf` 檔案
5. 下載到 `data/uploads/{projectId}/`
6. `.docx` 自動轉 `.md`（mammoth + turndown）

### 快取機制（三層）

1. **SVN 日期**：`svn info` 查 last modified，沒變就不下載
2. **SHA-256 hash**：下載後比對 hash，沒變就不重新轉換
3. **DB 記錄**：documents 表存 source_url + content_hash

### 注意事項

- Windows 上 TortoiseSVN 的 `svn list` 純文字輸出會把中文變 `?`，已改用 `--xml` 模式
- SVN URL 中的中文自動 percent-encode
- 下載用系統 temp 目錄避免 TortoiseSVN 路徑問題

## 11. Asana 任務整合

### 架構

`sync_asana_tasks` 直接用 PAT token 打 Asana REST API，不依賴 Web Server。

### 同步邏輯

1. 從 `global_config` 取 `asana.pat`
2. 從專案 `asana_project_gid` 取 Asana 專案 ID
3. 打 Asana API 取當前使用者的任務（含分頁）
4. Upsert 到本地 tasks 表
5. 5 分鐘內同步過自動跳過（force=true 覆蓋）

### 任務分類（regex）

| 標題關鍵字 | Label |
|-----------|-------|
| 前端、串接 | frontend |
| 後端 | backend |
| bug、fix、錯誤、失效 | task_type: bug |
| 新增、開發 | task_type: feature |

## 13. 注意事項與限制

### 模型

| 模型 | 說明 |
|------|------|
| Opus 4.6 | 最強品質，orchestrator 和 subagent 預設使用 |
| Sonnet 4.6 | 平衡速度和品質 |
| Haiku 4.5 | 最快，適合簡單任務 |

### 重要原則

1. **Orchestrator 不直接改專案程式碼** — 全部派 subagent
2. **不在 prompt 中摘要規格** — 只放檔案路徑
3. **每個專案有自己的 CLAUDE.md 和 skills** — subagent 自動讀取
4. **規格齊全才執行** — 缺 SA/SD 要告知使用者
5. **簡單功能合併 agent** — 避免衝突
6. **所有實作必須有規格依據** — 不可以自行編造

### Windows 特別注意

- `tsx watch` 在 Windows 上不穩定，改 `.ts` 後手動重啟
- SVN 輸出用 `--xml` 確保 UTF-8（避免 CP950 亂碼）
- SQLite 路徑含中文/空格時需注意編碼

### Agent 並行建議

同時執行的 subagent 不超過 5 個，避免系統資源不足。
