## 1. 系統需求與安裝

### Prerequisites

| 項目            | 版本需求  | 說明                                   |
| --------------- | --------- | -------------------------------------- |
| Node.js         | >= 18.0.0 | 執行環境                               |
| pnpm            | 最新版    | 套件管理工具                           |
| Claude Code CLI | 最新版    | AI Agent 核心，需已登入                |
| SVN CLI         | 1.14+     | SVN 規格文件抓取（TortoiseSVN 或 SlikSVN） |

---

### 安裝 Node.js

前往 [https://nodejs.org](https://nodejs.org) 下載 LTS 版本安裝。

安裝完確認：
```bash
node --version   # 應顯示 v18.x.x 以上
```

---

### 安裝 pnpm

```bash
# 方法一：用 npm 安裝（推薦）
npm install -g pnpm

# 方法二：Windows PowerShell
iwr https://get.pnpm.io/install.ps1 -useb | iex
```

安裝完確認：
```bash
pnpm --version
```

---

### 安裝 Claude Code CLI

```bash
npm install -g @anthropic-ai/claude-code
```

安裝完登入：
```bash
claude
```

首次執行會開啟瀏覽器進行 OAuth 登入，完成後即可使用。

確認已登入：
```bash
claude --version
```

> 重要：需先執行一次 `claude --dangerously-skip-permissions` 接受自動化權限，否則 Agent 無法自主執行工具。

---

### 安裝 SVN CLI（Windows）

OmniCommander 透過 `svn.exe` 從 SVN 抓取規格文件。系統會依序在以下位置尋找：

1. `C:\Program Files\TortoiseSVN\bin\svn.exe`
2. `C:\Program Files (x86)\TortoiseSVN\bin\svn.exe`
3. PATH 上的 `svn.exe`

**選項 A：TortoiseSVN（推薦，含 GUI）**

```powershell
# 用 winget 安裝，必須加 ADDLOCAL=ALL 才會包含 command-line tools
winget install --id TortoiseSVN.TortoiseSVN --custom "ADDLOCAL=ALL"
```

> ⚠️ TortoiseSVN 預設**不安裝** command-line tools。GUI 安裝精靈中需手動勾選「command line client tools」，winget 安裝則必須加 `--custom "ADDLOCAL=ALL"`，否則 `bin\svn.exe` 不會出現。

**選項 B：SlikSVN（純 CLI，較輕量）**

到 [https://sliksvn.com/download/](https://sliksvn.com/download/) 下載安裝，安裝程式會自動把 `svn.exe` 加入 PATH。

**確認安裝：**

```powershell
& "C:\Program Files\TortoiseSVN\bin\svn.exe" --version --quiet
svn --version --quiet  # 若已加入 PATH
```

### 安裝 SVN CLI（macOS）

```bash
brew install svn
```

> macOS 的 homebrew svn 可能不支援 NTLM 認證。系統會自動偵測並改用 `curl --ntlm` 方式存取 SVN（需要 curl，macOS 內建）。

---

### 安裝專案依賴

```bash
cd ai-omni-commander
pnpm install
```

## 2. 環境設定

在專案**根目錄**建立 `.env` 檔案：

```bash
# ===== 選填（有預設值）=====
PORT=3456                 # Server 監聽埠
DB_PATH=./data/omni.db    # SQLite 資料庫路徑

# ===== 選填（整合功能）=====
ASANA_PAT=               # Asana Personal Access Token（也可在 UI 設定）
```

> SVN 帳密、Asana PAT 也可以在 UI 的 Global Settings 設定，不一定要放 `.env`。

## 3. 啟動系統

```bash
# 同時啟動 Server + 前端（推薦）
pnpm dev

# 或分開啟動
cd server && pnpm dev     # Server: http://localhost:3456
cd web && pnpm dev        # 前端:   http://localhost:5173
```

開啟瀏覽器：`http://localhost:5173`

> **Windows 重要提醒**：`tsx watch` 在 Windows 上偵測檔案變更不穩定。修改 `.ts` 後請手動重啟 server（Ctrl+C → 重新 `pnpm dev`）。

## 4. 首次設定（必填）

### 進入 Global Settings

Sidebar 最底部 → 齒輪圖示「Global Settings」

---

### 4.1 SVN 設定

| 欄位     | 說明     | 範例          |
| -------- | -------- | ------------- |
| Username | SVN 帳號 | `simon.huang` |
| Password | SVN 密碼 | `xxxxxxxx`    |

填完後點「**Test**」確認連線成功，再點「**Save Global Settings**」。

> SVN 認證適用於所有專案，只需設定一次。

**Windows NTLM 認證說明：**
- TortoiseSVN 原生支援 NTLM/Negotiate 認證，直接填帳密即可
- 若 SVN server 使用 NTLM（如 VisualSVN Server），Windows 上不需額外設定
- macOS 若遇到 NTLM 認證失敗，系統會自動切換為 `curl --ntlm` 方式

**SSL 自簽憑證：**
- 系統自動加上 `--trust-server-cert` 和 `--trust-server-cert-failures` 旗標
- 自簽憑證的 SVN server 不需額外處理

---

### 4.2 Asana Personal Access Token（選填）

如需 Asana 任務整合，需填入 PAT：

1. 開啟 [Asana Developer Console](https://app.asana.com/0/my-apps) → Personal Access Tokens
2. 建立新 Token，複製
3. 貼入 Global Settings 的 **Asana PAT** 欄位
4. 點「**Test**」確認有效

> 每位使用者需填入**自己的** PAT，系統只會撈出指派給該 PAT 使用者的任務。

### 4.3 Global MCP Servers（選填）

| 選項           | 說明                                        |
| -------------- | ------------------------------------------- |
| Playwright MCP | 啟用後，Agent 可使用瀏覽器自動化工具（smoke test、E2E、整合測試） |

## 5. 建立專案

點擊 Sidebar 的「**+ New Project**」

### Step 1：選擇模式

| 模式              | 說明                                         | 適合場景                 |
| ----------------- | -------------------------------------------- | ------------------------ |
| **Spec Mode**     | 上傳 SA/SD 規格文件，Agent 按規格開發        | 有完整規格文件的正式開發 |
| **Creative Mode** | Architect Agent 訪談需求，自動生成規格再開發 | 需求不明確、探索性開發   |
| **Quick Mode**    | 單一 Agent 快速執行任務                      | 小修改、臨時任務         |

### Step 2：設定 Workspace

| 欄位  | 說明                     | 範例                         |
| ----- | ------------------------ | ---------------------------- |
| Label | Workspace 標籤           | `frontend`、`backend`        |
| Path  | 程式碼目錄的**絕對路徑** | `D:\Projects\MyApp\frontend` |

> 若要使用 **Fullstack 模式**，必須同時設定 Frontend Path 和 Backend Path。

### Step 3：上傳規格文件（Spec Mode）

支援格式：**PDF、DOCX、Markdown (.md)、純文字 (.txt)、圖片 (.png/.jpg)**

| 類型  | 說明                     | 自動偵測關鍵字         |
| ----- | ------------------------ | ---------------------- |
| SA    | System Analysis 需求規格 | 檔名含「規格」「需求」「SPEC」 |
| SD    | System Design 設計規格   | 檔名含「設計」「API」「SD」  |
| Other | 其他參考文件             | 其餘                   |

**DOCX 自動轉換**：`.docx` 上傳時自動轉為 Markdown（含圖片提取），Agent 透過 Read 工具讀取。

**文件路由規則**：Frontend Agent 收到 SA + SD；Backend Agent 只收 SD。

## 6. 任務管理與執行

### 6.1 任務標籤（Label）

| Label        | 說明 | Agent 工作目錄 |
|-------------|------|-------------|
| `frontend`  | 前端任務 | frontendPath |
| `backend`   | 後端任務 | backendPath |
| `fullstack` | 全端任務（見第 8 章）| 兩者都用 |
| `devops`    | 部署/基礎設施 | workingDir |
| `testing`   | 測試任務 | workingDir |
| `review`    | 程式碼審查 | workingDir |
| `architect` | 架構設計 | workingDir |

> `fullstack` 標籤只有在專案同時設定了 Frontend Path 和 Backend Path 時才會出現。

### 6.2 測試選項

展開任務後，可勾選測試選項：

**前端測試：**
- Smoke Test — 使用 Playwright 截圖驗證
- 產出 E2E Spec — 撰寫並執行 E2E 測試
- Console Script — 產生瀏覽器 Console 測試腳本
- Mock / Real API — 選擇測試時使用 mock 或真實 API

**後端測試：**
- 單元測試 — 撰寫並執行 unit tests
- API Smoke Test — 驗證 API 端點
- 產出 API 合約 — 輸出 API contract

**Fullstack 專用：**
- API 整合測試（Playwright） — 開瀏覽器驗證 FE→BE API 呼叫

### 6.3 執行任務

1. 展開任務 → 選擇模型（Sonnet / Opus / Haiku）
2. 勾選需要的測試選項
3. 點「**Execute**」

### 6.4 重要輸出標記

| 標記                | 說明                      |
| ------------------- | ------------------------- |
| `[TASK_COMPLETE]`   | 任務完成                  |
| `[NEEDS_HUMAN]`     | Agent 卡住，需要人工指引  |
| `[ENTITY_CHANGED]`  | DB/合約有異動             |
| `[REVIEW_COMPLETE]` | Code Review 完成          |
| `[FULLSTACK_FIX]`   | Fullstack Coordinator 分析結果 |

## 7. 監控與操作 Agent

### 7.1 Agent 頁面

Sidebar → 「Agents」

**List Mode（預設）**
- 左側：Agent 列表
- 右側：選中 Agent 的終端
- 同一 Fullstack 任務的 agents 會自動歸組（Group）

**Group 操作：**
- 點 Group 標題 → 右側分割顯示所有 agents（FE+BE 上方，Coordinator 下方）
- 點個別 agent → 右側只顯示該 agent
- Group 刪除 → 所有 agents 一起刪除

**Grid Mode**
- 點右上角 Grid 圖示切換
- 左側 checkbox 選擇要顯示的 agents
- 可拖放重排順序

### 7.2 終端輸出顏色

| 顏色           | 類型        | 說明                               |
| -------------- | ----------- | ---------------------------------- |
| 白色           | 文字        | Agent 回應                         |
| 藍色           | Tool Use    | 正在呼叫工具（讀檔、寫檔等）       |
| 綠色           | Tool Result | 工具執行結果                       |
| 紅色           | Error       | 錯誤訊息                           |
| 灰色           | System      | 系統訊息（auto-resume 等）         |
| 黃色（可折疊） | Thinking    | Agent 推理過程                     |

### 7.3 向 Agent 送指令

1. 選中 Agent → 底部輸入框輸入
2. 按 Enter 或點 Send
3. 可貼上圖片（Ctrl+V）一起送出
4. 終端出現 `[USER INSTRUCTION]` 確認已送達

### 7.4 Sidebar

- **預設展開**
- **點 Pin 按鈕**（左上角）→ 收合成 icon-only 模式
- **收合時** hover 自動展開（0.5 秒延遲）
- **再點 Pin** → 回到展開鎖定

## 8. Fullstack 全端任務

### 8.1 概述

Fullstack 模式讓前後端同時開發，完成後自動分析整合問題並修正。

### 8.2 前置條件

- 專案必須設定 **Frontend Path** 和 **Backend Path**
- 任務 Label 選擇 **fullstack**

### 8.3 執行流程

```
Phase 0: Coordinator Agent 啟動（主控，第一個出現在畫面）
    ↓
Phase 1: Frontend + Backend Agent 平行啟動
    ↓
Phase 2: 等待兩者完成
    ↓
Phase 3a: Coordinator 讀取兩份驗證報告，分析整合問題
    ↓
Phase 3b: Playwright 整合測試（若有勾選「API 整合測試」）
    ↓
Phase 4: 若有問題 → 修正指令送回原 FE/BE Agent 執行
          若無問題 → 任務完成
```

### 8.4 Agent 角色

| Agent | 角色 | 工作目錄 |
|-------|------|---------|
| Coordinator | 主控分析 | project workingDir |
| Frontend | 前端開發 | frontendPath |
| Backend | 後端開發 | backendPath |
| Integration Test | Playwright 測試（選填） | frontendPath |

### 8.5 Coordinator 分析內容

- API 路徑不一致（前端呼叫 `/api/hello`，後端實作 `/api/greeting`）
- 回應欄位不符（前端讀 `msg`，後端回傳 `text`）
- 資料型別差異
- 缺少端點（前端呼叫但後端未實作）
- 重複實作（同一端點在不同 service）

### 8.6 Grid 佈局

**3 個 agent（無整合測試）：**
```
┌──────────────┬──────────────┐
│   Frontend   │   Backend    │
├──────────────┴──────────────┤
│         Coordinator         │
└─────────────────────────────┘
```

**4 個 agent（有整合測試）：**
```
┌──────────────┬──────────────┐
│   Frontend   │   Backend    │
├──────────────┼──────────────┤
│ Coordinator  │ Integration  │
└──────────────┴──────────────┘
```

## 9. SVN 規格文件整合

### 9.1 設定步驟

1. **Global Settings** → 填入 SVN 帳號密碼 → Test → Save
2. **Project Settings** → 填入 SVN 路徑：
   - **Frontend Spec SVN Path**：前端規格文件的 SVN 目錄
   - **Backend Spec SVN Path**：後端規格文件的 SVN 目錄

SVN 路徑範例：
```
https://svn.example.com/svn/ProjectName/SA/前端SPEC/
https://svn.example.com/svn/ProjectName/SA/後端SPEC/
```

### 9.2 自動匹配規則

當 Asana 任務有 `parentName`（上層任務名稱），系統會：

1. 從名稱提取功能代碼（如 `OV0101` → root code `OV`）
2. 在 SVN 路徑下搜尋含 `OV` 的子目錄
3. 遞迴搜尋 `.docx` / `.pdf` 檔案
4. 用功能代碼比對檔名（如 `SPEC_OV01_銷項發票管理.docx`）
5. 自動下載並轉換為 Markdown（DOCX）或直接使用（PDF）

### 9.3 手動管理 SVN 檔案

展開任務 → SVN 自動匹配的文件會列在下方：
- 可點「**刪除**」移除不需要的文件
- 可用 **SVN Browser** 手動瀏覽並添加文件
- 文件會快取在 `data/uploads/{projectId}/`

### 9.4 Windows 特別注意

- **中文路徑**：SVN URL 中的中文字元會自動編碼，避免亂碼
- **Big5 / UTF-8**：系統自動偵測 SVN 回傳的編碼並轉換
- **NTLM 認證**：TortoiseSVN 原生支援，無需額外設定
- **自簽憑證**：自動加上 `--trust-server-cert-failures` 旗標

### 9.5 macOS 特別注意

- homebrew 安裝的 svn 可能不支援 NTLM 認證
- 系統會自動偵測並切換為 `curl --ntlm` 方式存取
- 需確保 `curl` 可用（macOS 內建）

## 10. 功能模組說明

### 10.1 Project Settings

Sidebar → Settings

| 設定項                 | 說明                                |
| ---------------------- | ----------------------------------- |
| Project Name           | 專案名稱                            |
| Frontend Path          | 前端程式碼目錄                      |
| Backend Path           | 後端程式碼目錄                      |
| Frontend Spec SVN Path | 前端規格 SVN 路徑                   |
| Backend Spec SVN Path  | 後端規格 SVN 路徑                   |
| Axure Share URL        | 原型網址                            |
| Frontend Extra Prompt  | 附加給前端 Agent 的額外指令         |
| Backend Extra Prompt   | 附加給後端 Agent 的額外指令         |
| Database Connections   | 外部資料庫連線設定                  |
| Asana Project GID      | 連結 Asana 專案                     |

**Gen Skills 按鈕**：出現在 Frontend/Backend Path 旁邊。
- 點擊後啟動 **Opus Skill Generator Agent**（`skill-gen` 角色）
- 自動深度分析專案程式碼
- 產生 CLAUDE.md（專案指南）和 .claude/skills/（技能檔案）
- 已有 CLAUDE.md 時使用 Edit 補強（不覆蓋現有內容）
- 產出的 CLAUDE.md 會包含「可用 Skills」章節

### 10.2 DB Schema Explorer

Sidebar → DB Schema

1. 在 Project Settings 新增 DB 連線（PostgreSQL / MySQL / MSSQL）
2. 點「**Fetch Schema**」撈取 schema
3. 檢視表格清單 + 欄位詳情 + ER 關聯圖

安全機制：唯讀、撈完斷線、僅執行 hardcoded information_schema 查詢。

### 10.3 SA Flow 流程圖

前端 Agent 終端 Header → 「**SA Flow**」按鈕

- 自動分析 SA 文件產生 Mermaid 操作流程圖
- 依 SHA-256 hash 快取（同內容不重複產生）
- 支援縮放、平移

### 10.4 Verification Report

Agent 終端 Header → 「**Report**」按鈕

- 查看 Agent 完成後產出的驗證報告（Markdown）
- 報告存於目標專案的 `docs/verification-reports/` 目錄

### 10.5 Asana 任務整合

**設定：**
1. Global Settings → 填入 Asana PAT
2. Project Settings → 填入 Asana Project GID

**功能：**
- 自動同步 Asana 任務（支援分頁，可處理 100+ 任務的大型專案）
- 只撈出指派給當前 PAT 使用者的任務
- 任務名稱自動匹配 SVN 規格文件
- 支援自動執行排程（5/15/30/60 分鐘間隔）

### 10.6 Mockup 管理

Sidebar → Mockup

- 連結 Axure Share 原型
- 使用 Playwright 自動爬取 HTML snapshot
- 產出語義化 HTML 供 Agent 參考 UI 設計

## 11. 資料夾結構

```
ai-omni-commander/
├── server/          # Backend（Node.js + Express）
├── web/             # Frontend（React + Vite）
├── shared/          # 共用 TypeScript 型別
├── docs/            # 文件（本手冊所在位置）
├── .env             # 環境設定（需自行建立）
├── .mcp.json        # MCP Server 設定（Playwright 等）
└── data/            # 執行期資料（自動建立，gitignore）
    ├── omni.db      # SQLite 主資料庫
    ├── uploads/     # 上傳的規格文件
    │   ├── {projectId}/           # 專案層級文件
    │   └── {projectId}/{agentId}/ # Agent 層級文件
    ├── sa-flows/    # SA 操作流程圖快取
    ├── schemas/     # 外部 DB Schema 快取
    └── spec-cache/  # SVN 規格文件快取
```

## 12. 注意事項與限制

### 伺服器重啟

修改後端 `.ts` 檔案後，在 **Windows 環境**需手動重啟 server（tsx watch 不穩定）。

### Claude Code CLI 認證

- 系統使用 Claude Code CLI，**不需要 API Key**
- CLI 必須已完成 `claude` 登入認證
- 必須已接受 `claude --dangerously-skip-permissions`

### Agent 並行建議

建議同時執行的 Agent 數量不超過 **5 個**，避免系統資源不足。

### 模型說明

| 模型   | 說明 | Context Window |
|--------|------|:-:|
| Sonnet | 平衡速度和品質（推薦）| 200K |
| Opus   | 最強品質，自動使用 1M context | 1M |
| Haiku  | 最快速，適合簡單任務 | 200K |

### 大型 PDF / DOCX

- 100 頁以上的 PDF 解析需較長時間
- `.docx` 自動轉 Markdown 並提取圖片
- 轉換後的 `.md` 和原始檔都保留在 `data/uploads/`
