## 1. 系統需求與安裝

### Prerequisites

| 項目            | 版本需求  | 說明                                   |
| --------------- | --------- | -------------------------------------- |
| Node.js         | >= 18.0.0 | 執行環境                               |
| pnpm            | 最新版    | 套件管理工具                           |
| Claude Code CLI | 最新版    | AI Agent 核心，需已登入                |
| SVN CLI         | 1.14+     | SVN 規格文件抓取，TortoiseSVN 或 SlikSVN |

---

### 安裝 Node.js

前往 [https://nodejs.org](https://nodejs.org) 下載 LTS 版本安裝。

安裝完確認：
```bash
node --version   # 應顯示 v18.x.x 以上
```

---

### 安裝 pnpm

```bash
# 方法一：用 npm 安裝（推薦）
npm install -g pnpm

# 方法二：Windows PowerShell
iwr https://get.pnpm.io/install.ps1 -useb | iex
```

安裝完確認：
```bash
pnpm --version
```

---

### 安裝 Claude Code CLI

```bash
npm install -g @anthropic-ai/claude-code
```

安裝完登入：
```bash
claude
```

首次執行會開啟瀏覽器進行 OAuth 登入，完成後即可使用。

確認已登入：
```bash
claude --version
```

若出現版本號即表示已正確安裝。

---

### 安裝 SVN CLI（Windows）

OmniCommander 透過 `svn.exe` 從 SVN 抓取規格文件。系統會依序在以下位置尋找：

1. `C:\Program Files\TortoiseSVN\bin\svn.exe`
2. `C:\Program Files (x86)\TortoiseSVN\bin\svn.exe`
3. PATH 上的 `svn.exe`

**選項 A：TortoiseSVN（推薦，含 GUI）**

```powershell
# 用 winget 安裝，必須加 ADDLOCAL=ALL 才會包含 command-line tools
winget install --id TortoiseSVN.TortoiseSVN --custom "ADDLOCAL=ALL"
```

> ⚠️ TortoiseSVN 預設**不安裝** command-line tools。GUI 安裝精靈中需手動勾選「command line client tools」，winget 安裝則必須加 `--custom "ADDLOCAL=ALL"`，否則 `bin\svn.exe` 不會出現。
>
> 若已安裝但缺 CLI，可重跑上面 winget 指令並加 `--force`，或在「應用程式與功能」找到 TortoiseSVN → 修改 → 勾選 command line tools。

**選項 B：SlikSVN（純 CLI，較輕量）**

到 [https://sliksvn.com/download/](https://sliksvn.com/download/) 下載安裝，安裝程式會自動把 `svn.exe` 加入 PATH。

**確認安裝：**

```powershell
# 任一行應顯示 svn 1.14.x 版本資訊
& "C:\Program Files\TortoiseSVN\bin\svn.exe" --version --quiet
svn --version --quiet  # 若已加入 PATH
```

## 2. 環境設定

在專案**根目錄**建立 `.env` 檔案：

```bash
# ===== 必填 =====
# 無（全部有預設值）

# ===== 選填（有預設值）=====
CLAUDE_PATH=auto          # Claude CLI 路徑。auto = 自動偵測，或填完整路徑如 C:\Users\xxx\AppData\Local\...
PORT=3456                 # Server 監聽埠
DB_PATH=./data/omni.db    # SQLite 資料庫路徑
DEFAULT_MODEL=sonnet      # 預設模型（sonnet / opus / haiku）
LOG_LEVEL=info            # 日誌等級（debug / info / warn / error）

# ===== 選填（整合功能）=====
ASANA_PAT=               # Asana Personal Access Token（也可在 UI 設定）
```

> **注意**：SVN 帳密、Asana PAT 也可以在 UI 的 Global Settings 設定，不一定要放 `.env`。

## 3. 啟動系統

```bash
# 同時啟動 Server + 前端（推薦）
pnpm dev

# 或分開啟動
pnpm dev:server   # Server: http://localhost:3456
pnpm dev:web      # 前端:   http://localhost:5173
```

開啟瀏覽器：`http://localhost:5173`

> **Windows 重要提醒**：`tsx watch` 在 Windows 上偵測檔案變更不穩定。修改 `.ts` 後請手動重啟 server（Ctrl+C → `pnpm dev:server`）。

## 5. 建立專案

點擊 Sidebar 的「**+ New Project**」

### Step 1：選擇模式

| 模式              | 說明                                         | 適合場景                 |
| ----------------- | -------------------------------------------- | ------------------------ |
| **Spec Mode**     | 上傳 SA/SD 規格文件，Agent 按規格開發        | 有完整規格文件的正式開發 |
| **Creative Mode** | Architect Agent 訪談需求，自動生成規格再開發 | 需求不明確、探索性開發   |
| **Quick Mode**    | 單一 Agent 快速執行任務                      | 小修改、臨時任務         |

---

### Step 2：設定 Workspace

每個 Workspace 代表一個工作目錄（前端或後端的程式碼目錄）。

| 欄位  | 說明                     | 範例                         |
| ----- | ------------------------ | ---------------------------- |
| Label | Workspace 標籤           | `frontend`、`backend`        |
| Path  | 程式碼目錄的**絕對路徑** | `D:\Projects\MyApp\frontend` |

點擊路徑輸入框旁的瀏覽圖示，可用伺服器端目錄瀏覽器選擇。

系統會自動掃描：

- 是否有 `CLAUDE.md`（專案指令文件）
- `.claude/` 目錄下有哪些 Skill 可用

---

### Step 3：上傳規格文件（Spec Mode）

支援格式：**PDF、Markdown (.md)、純文字 (.txt)、圖片 (.png/.jpg)**

**文件類型標記：**

| 類型  | 說明                     | 自動偵測關鍵字         |
| ----- | ------------------------ | ---------------------- |
| SA    | System Analysis 需求規格 | 檔名含「規格」「需求」 |
| SD    | System Design 設計規格   | 檔名含「設計」「API」  |
| Other | 其他參考文件             | 其餘                   |

上傳後可手動切換每個文件的類型。

**自動路由規則：**

- Frontend Agent 收到：SA + SD
- Backend Agent 收到：SD 只

---

### Step 4：執行設定

| 選項        | 說明                                                   |
| ----------- | ------------------------------------------------------ |
| Model       | 選擇 Agent 使用的 Claude 模型（sonnet / opus / haiku） |
| Superpowers | 啟用 Claude Code 進階功能（建議開啟）                  |
| Code Review | 任務完成後自動執行程式碼審查                           |
| Debug Mode  | 修改現有程式碼模式（非全新建立）                       |

點「**Create Project**」完成建立，系統自動開始執行。

## 6. 執行任務

### 6.1 Spec Mode 執行流程

```
上傳 SA/SD 文件
    ↓
系統分析文件，分發給 Frontend / Backend Agent
    ↓
（前端任務）自動分析 SA 文件，產生操作流程圖
    ↓
Agent 讀取 Workspace 的 CLAUDE.md 和 Skill
    ↓
逐步實作
    ↓
完成 [TASK_COMPLETE]
```

### 6.2 Agent 狀態說明

| 狀態     | 說明        |
| -------- | ----------- |
| idle     | 待機中      |
| starting | 正在啟動    |
| running  | 執行中      |
| stopped  | 已完成/停止 |
| error    | 發生錯誤    |

### 6.3 重要輸出標記

Agent 的終端輸出中會出現以下特殊標記：

| 標記                | 觸發事件     | 說明                      |
| ------------------- | ------------ | ------------------------- |
| `[TASK_COMPLETE]`   | 任務完成     | 全部工作完成              |
| `[NEEDS_HUMAN]`     | 人工介入請求 | Agent 卡住，需要人工指引  |
| `[ENTITY_CHANGED]`  | 實體更新     | DB/合約有異動             |
| `[SPEC_READY]`      | 規格生成完成 | Creative Mode：規格已生成 |
| `[REVIEW_COMPLETE]` | 審查完成     | Code Review Agent 完成    |

### 6.4 人工介入（Intervention Bell）

Header 右側的鈴鐺圖示出現紅點時，表示有 Agent 需要協助。

1. 點擊鈴鐺圖示
2. 查看 Agent 的問題描述
3. 選擇：
   - **Approve**：確認繼續
   - **Reject**：拒絕並指示其他方向
4. 可在輸入框補充說明

## 7. 監控與操作 Agent

### 進入 Agents 頁面

Sidebar → 「Agents」（或 Dashboard 的 Agent 卡片）

---

### 7.1 終端輸出

Agent 執行時，終端會即時顯示所有輸出：

| 顏色           | 類型        | 說明                               |
| -------------- | ----------- | ---------------------------------- |
| 白色           | 文字        | 一般 Agent 回應                    |
| 藍色           | Tool Use    | Agent 正在呼叫工具（讀檔、寫檔等） |
| 綠色           | Tool Result | 工具執行結果                       |
| 紅色           | Error       | 錯誤訊息                           |
| 灰色           | System      | 系統訊息                           |
| 黃色（可折疊） | Thinking    | Agent 的推理過程                   |

---

### 7.2 向執行中的 Agent 送指令

1. 點擊目標 Agent 的終端（進入焦點模式）
2. 在底部輸入框輸入指令
3. 按 **Enter** 送出
4. 終端出現 `[USER INSTRUCTION]` 標記確認已送達

**適合的指令範例：**

- 「請不要修改 xxx 元件，只調整 yyy 部分」
- 「這個 API 路徑要改成 /api/v2/orders」
- 「你卡住了，請繼續執行下一步」

---

### 7.3 顯示模式切換

**List Mode（列表模式，預設）**

- 左側：Agent 列表
- 右側：選中 Agent 的終端

**Grid Mode（網格模式）**

1. 點擊 Grid 按鈕切換
2. 點擊 Agent 卡片上的 Pin 圖示，加入網格
3. 最多可同時顯示多個終端
4. 可拖放重排順序
5. 切換專案時，Grid 選取會自動清空

---

### 7.4 新增 Agent

點擊「**Add Agent**」按鈕：

| 欄位                    | 說明                                                           |
| ----------------------- | -------------------------------------------------------------- |
| Role                    | 角色（backend / frontend / devops / testing / review / quick） |
| Model                   | 模型（sonnet / opus / haiku）                                  |
| Prompt                  | 自訂系統提示（可空白使用預設）                                 |
| Working Directory       | 工作目錄（自動填入或手動指定）                                 |
| Enable Workspace Skills | 啟用 workspace 的 CLAUDE.md 和 Skill                           |
| Enable Superpowers      | 啟用進階功能                                                   |
| Files                   | 上傳 SA/SD 文件給此 Agent                                      |
| Mockup Files            | 上傳設計稿圖片                                                 |

---

### 7.5 SA Flow 流程圖

前端 Agent 執行前，系統會自動分析 SA 文件並產生操作流程圖（Mermaid 格式）。

**查看方式：**

1. 前端 Agent 終端 Header → 「**SA Flow**」按鈕（紫色）
2. 點擊後開啟流程圖 Modal
3. 若有多個 SA 文件，可用下拉選單切換
4. 支援縮放、平移

> 同一份 SA 內容（依 SHA-256 hash 判斷）只會產生一次，之後使用快取。

## 8. 迭代開發（追加執行）

專案完成後，可繼續追加新的規格文件並重新執行。

**操作步驟：**

1. Dashboard → 下方「**New Execution**」面板
2. 上傳新的 SA/SD 文件（舊文件保留）
3. 點「**Start Execution**」
4. 系統以所有文件（舊 + 新）重新啟動 Agent
5. 舊 Agent 的終端輸出保留可查詢

## 9. 功能模組說明

### 9.1 Project Settings（專案設定）

路徑：Sidebar → Settings → 選擇專案

| 設定項                 | 說明                                                                          |
| ---------------------- | ----------------------------------------------------------------------------- |
| Project Name           | 專案名稱                                                                      |
| Frontend Path          | 前端程式碼目錄                                                                |
| Backend Path           | 後端程式碼目錄                                                                |
| Frontend Spec SVN Path | 前端規格文件的 SVN 路徑<br>例：`https://svn.example.com/svn/Proj/SA/前端SPEC` |
| Backend Spec SVN Path  | 後端規格文件的 SVN 路徑                                                       |
| Axure Share URL        | 原型網址（例：`https://xxxxxx.axshare.com`）                                  |
| Frontend Extra Prompt  | 附加給前端 Agent 的額外指令（Markdown 支援）                                  |
| Backend Extra Prompt   | 附加給後端 Agent 的額外指令                                                   |
| Database Connections   | 外部資料庫連線設定（見 9.2）                                                  |
| Asana Project GID      | 連結 Asana 專案 ID                                                            |

> **Gen Skills 按鈕**：出現在 Frontend/Backend Path 旁。點擊後 AI 自動掃描程式碼，生成客製化的 Skill 文件放入 `.claude/skills/`。

---

### 9.2 DB Schema Explorer（外部資料庫瀏覽）

**設定連線：**
Project Settings → Database Connections → 「+ 新增連線」

| 欄位              | 說明                       |
| ----------------- | -------------------------- |
| Label             | 連線名稱（顯示用）         |
| Type              | PostgreSQL / MySQL / MSSQL |
| Connection String | 完整連接字串               |

**Connection String 格式：**

```
# PostgreSQL
postgresql://user:password@host:5432/database

# MySQL
mysql://user:password@host:3306/database

# MSSQL（標準格式）
mssql://user:password@host:1433/database

# MSSQL（ADO.NET 格式）
Server=host;Database=mydb;User Id=user;Password=pass;
```

**操作流程：**

1. Sidebar → 「DB Schema」進入瀏覽器
2. 頂部顯示所有已設定的 DB 連線卡片
3. 點擊卡片上的「**Fetch Schema**」按鈕（⚠️ 只有此按鈕可觸發，不會自動撈取）
4. 等待連線成功，下方出現：
   - **Schema 頁籤**：表格清單（左）+ 欄位詳情（右）
   - **ER Diagram 頁籤**：自動產生的 Mermaid ER 關聯圖

**安全機制：**

- 連線後自動設為唯讀（不可執行任何 DML/DDL）
- 撈完 schema 立即關閉連線（不保持長連線）
- 僅執行 hardcoded `information_schema` 查詢，無法執行任意 SQL

---

### 9.3 Internal DB（內建 SQLite 瀏覽器）

Sidebar 最外層 → 「Internal DB」

用於查看 OmniCommander 自身的 SQLite 資料庫（`data/omni.db`），供開發除錯用。

---

### 9.4 SVN Browser

Dashboard 工具列 → SVN Browser 按鈕

- 輸入 SVN Repository 路徑
- 瀏覽目錄樹
- 查看文件列表
- 直接選擇規格文件下載給 Agent 使用

---

### 9.5 Asana 任務整合

**連結 Asana：**

1. Project Settings → Asana Project GID
2. 輸入 Asana 專案的 GID（URL 中的數字）
3. 點「Sync Now」同步任務

**任務卡片（Task List）：**

- 顯示從 Asana 同步的任務
- 每個任務可設定：
  - 描述（Description）
  - 類型（feature / bug / testing）
  - 分配的 Agent
- 點擊任務可展開查看詳情
- 支援手動新增本地任務

**SVN 自動匹配：**

- Agent 執行時，依據 Asana 任務名稱中的代碼（如 `OV0101`）
- 自動在 SVN 規格路徑下搜尋對應文件（`.docx`/`.pdf`）
- 找到後自動下載並轉換給 Agent 使用

## 10. 資料夾結構

```
ai-omni-commander/
├── server/          # Backend（Node.js + Express）
├── web/             # Frontend（React + Vite）
├── shared/          # 共用 TypeScript 型別
├── docs/            # 文件（本手冊所在位置）
├── .env             # 環境設定（需自行建立）
└── data/            # 執行期資料（自動建立）
    ├── omni.db      # SQLite 主資料庫
    ├── uploads/     # 上傳的規格文件
    │   ├── {projectId}/           # 專案層級文件
    │   └── {projectId}/{agentId}/ # Agent 層級文件
    ├── sa-flows/    # SA 操作流程圖快取（.mmd + meta.json）
    ├── schemas/     # 外部 DB Schema 快取
    └── spec-cache/  # SVN 規格文件快取
```

## 11. 注意事項與限制

### 伺服器重啟

修改後端 `.ts` 檔案後，在 **Windows 環境**需手動重啟 server（tsx watch 不穩定）。

### Claude Code CLI 認證

系統使用 Claude Code CLI 執行所有 AI 任務，不使用 API Key。
CLI 必須已完成 `claude` 登入認證，否則 Agent 無法啟動。

### Agent 並行建議

建議同時執行的 Agent 數量不超過 **5 個**，避免系統資源不足。

### 資料庫安全

外部 DB 連線：

- 連線字串不會傳到前端
- 僅執行唯讀的 schema 查詢
- 每次操作後立即斷線

### 大型 PDF 文件

100 頁以上的 PDF 解析可能需要較長時間，請耐心等待上傳完成。

### DOCX 文件

`.docx` 上傳時自動轉換為 Markdown，原始檔與轉換後的 `.md` 均保留在 `data/uploads/`。

### SVN 路徑設定

SVN 規格路徑需精確到**文件所在的目錄層級**，Agent 會遞迴搜尋目錄下所有 `.docx`/`.pdf` 文件。
